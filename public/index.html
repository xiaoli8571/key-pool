v1.0

添加渠道（平台）自定义 Base URL，支持 OpenAI / Anthropic / Gemini / Azure 等任何兼容平台

提示：Base URL 填到域名或 /v1 均可（如 https://api.example.com 或 https://tierflow.cn/v1）

轮换策略

并发策略：最少并发优先 + 单 Key 并发上限；429 遵循上游 Retry-After

运行日志

Agent / 客户端接入

把 Agent 的 API 地址改为本服务即可，所有请求会自动在多个密钥间轮换：

响应头 x-keypool-target / x-keypool-key 显示本次实际使用的渠道与密钥；429/5xx/超时会自动换下一个密钥重试；所有密钥都在冷却时返回 429 + Retry-After。

也支持 Anthropic 协议 POST /v1/messages（x-api-key 头）与 Gemini 原生路径 /v1beta/*。

🔐 渠道专属 Key

在每个渠道里可以生成专属 Key（自动生成 kp-渠道名-xxxx 或手动填写）。把它填进 Agent 后，该 Agent 的请求只会路由到这个渠道，看不到其他渠道和模型；并独立统计请求数。适合"一个渠道发一个 Agent"的隔离场景。全局网关密钥（设置页）则可访问所有渠道。

编辑渠道

适用于原生暴露 /v1/messages 的 OpenAI 兼容平台（如 tierflow、SenseAudio），可让 Claude 类客户端直接用本渠道的专属 Key
过滤上游标记为非对话的模型（TTS/ASR/图像等）；模型池与 /v1/models?all=1 仍显示全部
